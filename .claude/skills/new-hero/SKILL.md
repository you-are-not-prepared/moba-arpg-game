# New hero (moba-arpg-game)

Heroes are generated by code:
- `Assets/_Project/Editor/GameBuilder.cs`: the hero list (`Heroes()`), prefabs, and the older ultimates (Skybreaker Arrow, Rewind, Aegis Wall…).
- `GameBuilder.Kits.cs`: signature spells, the newer unique ultimates and the shared ultimates, plus the builder helpers.
- `GameBuilder.Ascension.cs`: the ascension trees.

Running **MOBA > Rebuild All Scenes** writes the assets: `Assets/_Project/Heroes/Hero_<Name>.asset`, `Sig_*.asset`, `Ult_*.asset`, the `HeroRoster`, and `Prefabs/Hero_<Name>.prefab`. Never hand-edit those assets; change the builder and rebuild.

Everything else picks the hero up from the roster on its own: champion select, bots' random picks, the shop, match history, the network prefab list (`NetItems` registers signatures and every ultimate option) and the game server.

## What every hero has

- **Identity:** `Id` (lowercase, `^[a-z0-9_]+$`, also stored in match history, so don't rename later), `Name`, `Title`, one-letter `Glyph`, `Color`, and a one-line `Description`.
- **Base stats:** `Health`, `Damage`, `Range` (melee ≈ 1), `AttacksPerSecond`, `Speed`, `Mana`. Set `Melee = true` for melee (no attack projectile).
  - **Today's ranges:** HP 560–700, damage 30–40, speed 6.0–6.8, mana 300.
- **Damage identity:**
  - `Resistances = Res(fire, frost, nature, lightning, physical, air)` in percent. They only change the damage the hero takes (+25 = 25% less from that type); the highest one is the hero's **base damage type**. The usual pattern is +25 on the base type, a small plus on one or two others, and minuses on the types the base is weak to or strong against.
  - The cycle is Fire > Frost > Nature > Lightning > Physical > Air > Fire: +10% against the next type, −10% against the previous one.
  - `SpellColors = Colors(Rgb(...), Rgb(...), Rgb(...))`: three colours for the hero's spell looks.
- **A passive.** `PassiveName` and `PassiveDescription` are shown in champion select, plus the numbers the passive uses.
- **A signature spell** in **Q** (`Signature = m => <Name>(m)`):
  - unique to the hero, adaptive (takes the hero's type and look);
  - costs 300 and sells back at full price;
  - the hero's shop lists it in a Signature section so it can be rebought.
- **Three ultimates**, chosen at level 6; the pick goes into **R**, locked:
  - two are unique to the hero;
  - one is shared by every hero with the same base type and melee/ranged:

    | Type | Ranged | Melee |
    |---|---|---|
    | Physical | Arrow Storm | Whirlwind |
    | Lightning | Thunderstrike | – |
    | Fire | Meteor | Inferno |
    | Air | Cyclone | – |
    | Frost | Blizzard | – |
    | Nature | Overgrowth | – |

  - a new type/range pair needs a new shared ultimate in `GameBuilder.Kits.cs`.
- **Ascension at levels 6, 11 and 16,** which give no skill point (Q/W/E get the other 15):
  - level 6 picks a path, and so the ultimate (R rank 1);
  - levels 11 and 16 each offer two talents from that path (R ranks 2 and 3);
  - every talent upgrades the chosen ultimate **and** the passive.

## Steps

1. **Pin down the design with the user** if the proposal leaves gaps: numbers, melee/ranged, resistances, what the signature and the two unique ultimates do.
2. **HeroSpec:** add an entry to `Heroes()` in `GameBuilder.cs`. Copy the closest existing hero; keep the field order and the one-line comment style.
3. **Passive:**
   - **An existing passive field fits:** use it. The fields are `ExtraProjectiles`, `CooldownMultiplier`, `ItemStatMultiplier`, `HealthPerLevelBonus`, `MoveSpeedMultiplier`, and `IsolationDamageBonus` with `IsolationRadius`, plus the component passives (Tailwind, Kindled Blade's Heat, slow, charge).
   - **New mechanic:** add a field to `HeroSpec` and to `HeroDefinition` (`Scripts/Match/HeroDefinition.cs`), copy it across in `CreateHeroes`, apply it in `HeroDefinition.ApplyTo`, and write any behaviour as a component, like `Heroes/IsolationPassive.cs`.
4. **Signature spell:** add a method to the signature section of `GameBuilder.Kits.cs`, like `PiercingShot(m)` or `ShieldBash(m)`.
   - Start from `Signature<T>(id, name, glyph, color, description, cooldowns, manaCosts)`, which writes `Sig_<id>.asset`.
   - Fill it with `Shot(...)`, `Blast(...)` or `Strike(...)`, and end with `Done(...)`.
5. **Unique ultimates:**
   - **An existing type fits:** use `Ultimate<T>(id, name, glyph, color, description, type, adaptive, cooldowns, mana)`, which writes `Ult_<id>.asset`. Set `cooldownByRank` for 3 ranks. The types:

     | Type | Does |
     |---|---|
     | `ProjectileSpell` | damage, pierce, stun, slow, chain, explosion, cooldown refund |
     | `BurstSpell` | delayed area hit; a line with `count`/`spacing`; stun, slow, burn |
     | `MeleeSpell` | cone or lunge; stun, execute, Heat stacks |
     | `ZoneSpell` | lingering ground zone |
     | `LeapSpell` | leap and slam |
     | `StormCloudSpell` | |
     | `BuffSpell` | timed stats: attack speed, range, move speed, damage reduction |
     | `AuraSpell` | hits around the caster every interval |
     | `HealSpell` | one ally, or every ally in an area |
     | `HasteSpell` | |
     | `ShieldWallSpell` | |
     | `CooldownResetSpell` | |
     | `ExtraSocketUltimate` | passive, extra mod sockets |

   - **New spell type:** subclass `AbilityDefinition` in `Scripts/Abilities`, implement `Execute` (plus `Describe` and `StatsText` for tooltips), and give timed effects a component like `Heroes/Buff.cs`.
     - Read `context.Modifiers`: `damageMultiplier`, `damageType`, and `Radius()` for areas, so that spell-damage bonuses and ultimate talents apply.
     - Add a case to `BotBrain` so bots cast it.
6. **Ascension:** add `<Name>Ascension(Mats m)` to `GameBuilder.Ascension.cs` with `Tree("<id>", passives, paths...)`:
   - **`passives`:** four `P(flavor, t => ...)` passive upgrades, in order: the two level-11 options, then the two level-16 options.
   - **Each path:** `(UltimateMethod(m), Ups(U(Up.X, value) × 4))`, with the ultimate upgrades paired with the passives in the same order.
     - `Up` is one of Damage, Cooldown, Duration, Radius, Stun or Items.
     - Put the two unique ultimates first and the shared one last.
   - **Generated for you:**
     - Talent names come from the upgrade, e.g. "Empowered X" or "Mighty X".
     - Ids are `<id>_a`, `<id>_a1`..`a4`, and the same for `b` and `c`.
     - The path root's text is the ultimate's description.
   - **Passive talent fields:** maxHealth, maxMana, attackDamage, attackSpeed, moveSpeed, cooldownReduction, spellDamage, extraProjectiles, itemStats, healthPerLevel, isolationDamage, stunDuration, tailwindSpeed/Duration/AttackSpeed, heatBurstDamage, spellSlow/SlowSeconds, allyHeal, chainJumps, chargeSooner.
   - **Hook it up:** set `Ascension = <Name>Ascension` in the HeroSpec.
7. **Game server (PvP):** abilities and passives run on the server, and clients only see what's synced. New mechanics need a look:
   - **Damage, health, stun, burn:** already synced (NetworkUnit).
   - **New visuals:**
     - Projectiles, explosions and per-type looks go through `SpellProjectile`, `SpellExplosion` and `SpellLook` (already broadcast via NetworkMatch).
     - A new timed buff needs a timer in `NetworkHero.PushState`/`ApplyState`, like `_hasteEnd`, `_shieldEnd` and `_buffEnd`, plus a `SyncFromServer` on its component.
     - Materials referenced by public `Material` fields of a spell asset get network ids automatically (`NetItems`).
   - **New per-hero numbers that the HUD shows:** sync them in `NetworkHero`.
8. **Rebuild:**
   - Compile, then run `MOBA > Rebuild All Scenes` (`ev 'Moba.EditorTools.GameBuilder.BuildAll(); return "ok";'`). It's long, so wait and check `errors`.
   - Rebuild and redeploy the game server (game-server-deploy).
   - Afterwards reopen `Frontend.unity`.
9. **Test** (unity-playtest; pvp-e2e-test for PvP):
   - **Champion select:** the hero shows its type badge and resistance hexagon, passive, signature, and the three ultimate options.
   - **Offline match as the hero:**
     - stats, the passive and the signature (Q) work;
     - cheat to level 6, check there's no skill point, pick a card, and check the ultimate is in R at rank 1 and can be cast;
     - check the talents and R ranks at 11 and 16;
     - sell the signature (full price) and buy it back.
   - **As a bot:** the hero also works when a bot plays it.
   - **PvP:** the signature, the ultimates and their visuals on a client connected to the game server.
10. **README:** add a row to the **Heroes** table in `README.md` (hero, passive, signature, ultimates) and to the base-type table below it. If the hero introduced a new mechanic or shared ultimate, describe it where the README covers that system.
11. Ship when the user asks (the ship skill).

## Notes

- Changing a hero's `Id` or an item's asset name breaks recorded match history (both are stored as ids). Add new ones instead.
- Hero proposals from Discord and the concept write-ups live in the `moba-arpg-ideas` repo (`heroes/`; the kit rules are in `game-mechanics/hero-kit-rework`). Link the idea folder in the PR if there is one.
