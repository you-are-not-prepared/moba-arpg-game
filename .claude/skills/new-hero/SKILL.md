# New hero (moba-arpg-game)

Heroes are generated by code: `Assets/_Project/Editor/GameBuilder.cs` (the hero list, prefabs, ultimates) and `GameBuilder.Ascension.cs` (talent trees). Running **MOBA > Rebuild All Scenes** writes the assets: `Assets/_Project/Heroes/Hero_<Name>.asset`, `Ult_*.asset`, the `HeroRoster`, and `Prefabs/Hero_<Name>.prefab`. Never hand-edit those assets; change the builder and rebuild.

Everything else picks the hero up from the roster on its own: champion select, bots' random picks, the shop, match history, the network prefab list and the game server.

## What every hero has

- **Identity:** `Id` (lowercase, `^[a-z0-9_]+$`, also stored in match history, so don't rename later), `Name`, `Title`, one-letter `Glyph`, `Color`, and a one-line `Description`.
- **Base stats:** `Health`, `Damage`, `Range` (melee ≈ 1), `AttacksPerSecond`, `Speed`, `Mana`. Set `Melee = true` for melee (no attack projectile).
  - **Today's ranges:** HP 560–700, damage 30–40, speed 6.0–6.8, mana 300.
- **A passive.** `PassiveName` and `PassiveDescription` are shown in champion select, plus the numbers the passive uses.
- **An ultimate,** locked into **R** (Q/W/E are bought in the shop).
- **An ascension tree** with 2–4 paths (A, B, C...):
  - level 6 picks the path, levels 11 and 18 each offer two talents from it;
  - by convention **A** builds on the passive, **B** on the ultimate, and **C** is a hybrid of both.

## Steps

1. **Pin down the design with the user** if the proposal leaves gaps: numbers, melee/ranged, how the ultimate behaves, what the three paths are about.
2. **HeroSpec:** add an entry to `Heroes()` in `GameBuilder.cs`. Copy the closest existing hero; keep the field order and the one-line comment style.
3. **Passive:**
   - **An existing passive field fits:** use it. The fields are `ExtraProjectiles`, `CooldownMultiplier`, `ItemStatMultiplier`, `HealthPerLevelBonus`, `MoveSpeedMultiplier`, and `IsolationDamageBonus` with `IsolationRadius`.
   - **New mechanic:** add a field to `HeroSpec` and to `HeroDefinition` (`Scripts/Match/HeroDefinition.cs`), copy it across in `CreateHeroes`, apply it in `HeroDefinition.ApplyTo`, and write any behaviour as a component, like `Heroes/IsolationPassive.cs`.
4. **Ultimate:**
   - **An existing type fits:** write a builder method like `SkybreakerArrow(m)` / `Bloodrush(m)` that fills a `LoadOrCreate<...>($"{HeroesDir}/Ult_<Name>.asset")`. The available types:
     - `ProjectileSpell`: damage, pierce, stun, explosion;
     - `HasteSpell`: timed speed buff;
     - `ShieldWallSpell`: projectile wall;
     - `CooldownResetSpell`;
     - `ExtraSocketUltimate`: passive, extra mod sockets.
   - **New ultimate type:** subclass `AbilityDefinition` in `Scripts/Abilities`, implement `Execute` (plus `Describe` and `StatsText` for tooltips), and give timed effects a component like `Heroes/Haste.cs`.
   - Set `cost = 0`, a 2-letter `glyph`, `cooldownByRank` (3 ranks, learned at levels 6/11/16), `manaCostByRank` and `targeting`.
5. **Ascension:** add `<Name>Ascension()` to `GameBuilder.Ascension.cs` with `AscPath(T(...), ...)` × 3 paths.
   - **Talent ids:** `<id>_a`, `<id>_a1`..`a4`, and the same for `_b` and `_c`.
   - **Talent fields:** maxHealth, maxMana, attackDamage, attackSpeed, moveSpeed, cooldownReduction, ultimateCooldownReduction, spellDamage, extraProjectiles, itemStats, healthPerLevel, isolationDamage, ultimateDuration, stunDuration.
   - **Each talent** gets a short name and a flavour line.
   - **Hook it up:** set `Ascension = <Name>Ascension` in the HeroSpec.
6. **Game server (PvP):** abilities and passives run on the server, and clients only see what's synced. New mechanics need a look:
   - **Damage, health, stun, burn:** already synced (NetworkUnit).
   - **New visuals:**
     - Projectiles and explosions go through `SpellProjectile` and `SpellExplosion` (already broadcast via NetworkMatch).
     - A new timed buff needs a timer in `NetworkHero.PushState`/`ApplyState`, like `_hasteEnd` and `_shieldEnd`, plus a `SyncFromServer` on its component.
     - Materials referenced by public `Material` fields of the ultimate asset get network ids automatically (`NetItems`).
   - **New per-hero numbers that the HUD shows:** sync them in `NetworkHero`.
7. **Rebuild:** compile, run `MOBA > Rebuild All Scenes` (`ev 'Moba.EditorTools.GameBuilder.BuildAll(); return "ok";'`; it's long, so wait and check `errors`), then rebuild and redeploy the game server (game-server-deploy). Afterwards reopen `Frontend.unity`.
8. **Test** (unity-playtest; pvp-e2e-test for PvP):
   - **Champion select:** the hero shows with its passive and ultimate text.
   - **Offline match** as the hero:
     - stats and the passive work;
     - cheat to level 6 and learn R, then cast it;
     - pick an ascension path, and check the talents at 11 and 18.
   - **As a bot:** the hero also works when a bot plays it.
   - **PvP:** the ultimate and its visuals on a client connected to the game server.
9. **README:** add a row to the **Heroes** table in `README.md` (hero, passive, ultimate). If the hero introduced a new mechanic, describe it where the README covers that system.
10. Ship when the user asks (the ship skill).

## Notes

- Changing a hero's `Id` or an item's asset name breaks recorded match history (both are stored as ids). Add new ones instead.
- Hero proposals from Discord and the concept write-ups live in the `moba-arpg-ideas` repo (`heroes/`). Link the idea folder in the PR if there is one.
